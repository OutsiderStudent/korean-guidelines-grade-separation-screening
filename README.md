# Korean Guidelines-Based Grade Separation Screening

**Traffic Volume and Capacity Assessment**  
한국어 프로그램명: **입체화검토** · 약칭: **K-GSS** · 버전: **v5.1.0**

made by NYH · dmecyh@naver.com

국토교통부 「교차로 설계지침(2025)」과 「도로용량편람(2026)」을 참고하여 제작한 입체교차 개략검토 프로그램입니다.

> K-GSS is a Korean-guidelines-based desktop tool for screening intersection grade-separation needs using traffic volume and capacity.

국토교통부 「교차로 설계 지침(2025.06)」의 `1.4.2 교통량과 입체교차의 관계`에 따라 교통량과 용량의 A·B·C·D 영역을 검토하는 Windows 데스크톱 프로그램입니다.

## 주요 기능

- 3·4·5·6지 교차로 선택과 고정 방향 코드(SB, NB, WB, EB, SEB, SWB, NWB, NEB)
- 접근로별 편도 본선 차로수, 좌회전·직진·우회전 시간교통량, 중차량 비율 입력
- 분석 방식 → 도로·회전 → 차로·교통량 → 신호 → 확인·근거 순서의 상세 설정
- 접근로별 폭·경사·보호좌회전 반경/교차각·우회전 조건으로 보정계수 자동 산정
- 동일 진입신호를 사용하는 차로의 실측 교통량 기반 용량·포화도 참고 검토
- 서로 마주 보는 두 도로축이 있는 4지는 지침 용량 도표로 검토
- 3지·불규칙한 4지·5지·6지는 신호주기 내 이동류별 처리 가능 여부 검토
- 71 mm × 71 mm 보고서용 그래프 클립보드 복사 및 PNG 저장
- 상세 그래프와 모든 그래프 일괄 저장
- 프로젝트 새로 만들기·열기·저장·다른 이름으로 저장(`.igr3`)
- `.igr3` 파일 더블클릭 시 K-GSS 실행과 동시에 해당 프로젝트 자동 불러오기
- 지침 원문 페이지, 적용 공식, 출처와 프로그램 가정을 확인하는 `지침·공식` 탭
- NanumSquare Light·Regular·Bold·ExtraBold와 전용 아이콘을 포함한 단일 portable EXE
- 네이비 중심의 공통 디자인 시스템과 시스템·라이트·다크 테마
- 실행 시 GitHub Release의 최신 버전을 자동 확인하고 SHA-256 검증 후 CPU에 맞는 x64·ARM64 버전으로 업데이트
- 현재 단계 표시, 화면 전환 페이드, 마우스·키보드 버튼 축소·스프링 복귀 효과 (`KGSS_REDUCE_MOTION=1`로 모션 끄기)

## 계산 원칙과 출처 구분

- A·B·C·D 경계, `C = 1,800 × 편도 본선 차로수`, P·P′ 구조 및 예시는 「교차로 설계 지침(2025.06)」 PDF 244~247쪽(인쇄면 235~238쪽)을 따릅니다.
- 자동 보정은 이동류식 `fM = 1/Σ(pM×EM)`과 경사·차로폭·중차량 보정식을 적용합니다.
- 기본값은 평지, 차로폭 3.0m, 보호좌회전 `E=1.08`, 녹색신호 우회전 `E=1.20`, 중차량 `EHV=1.8`이며 입력 확인 화면과 부록에 공개합니다.
- 자동 보정은 동일 조건을 가정한 접근로 단위 근사입니다. 차로·현시별 용량, 대기행렬, 지체와 서비스수준은 별도 분석 범위입니다.
- 이전 프로젝트는 원래 자동식이나 직접 입력 계수를 유지합니다. 상세 보정 설정에서 개략 자동 보정으로 전환할 수 있으며, 저장할 때는 다른 파일 이름을 사용합니다.
- 별도 분석계수가 있으면 접근로별 통합 회전계수와 중차량계수를 직접 입력할 수 있습니다. 2025 지침 예제의 명시 계수는 직접 입력 회귀시험으로 q, C, P, P′ 및 영역 C를 재현합니다.
- P′ 기본값은 지침 예제의 `(C + 600) × 0.9 + 2 × 3,600 / 36`이며 상세 설정에서 근거값을 변경할 수 있습니다.
- 판정에는 백 단위 표시값이 아닌 원시 계산값을 사용합니다.
- 4지라도 대향 도로축이 두 개가 아니면 신호계획을 입력합니다. 대향축이 두 개여도 입력 확인 화면에서 신호계획 검토를 선택할 수 있습니다.
- 신호계획 검토에는 진출로, 설계 시간교통량, 보정 포화교통류율, 차로군과 통행 현시를 입력합니다. 같은 현시에 배정한 이동류 경로가 교차하면 입력을 수정해야 합니다. 합류·보행 상충, 실제 동시 통행 가능 여부는 현장 신호·차로 운영을 기준으로 확인합니다.
- 필요 녹색은 `신호주기 × 교통량 ÷ 보정 포화교통류율`입니다. 같은 현시에 통행하는 공용차로군은 이동류별 필요 시간을 합산합니다. 서로 다른 현시를 사용하는 공용차로군은 대기차량의 차단을 반영한 별도 용량 검토가 필요합니다.
- 신호 결과는 입력한 계획의 처리 가능 여부와 녹색 부족 시간을 표시합니다. 기존안과 개선안의 신호시간·포화교통류율을 각각 입력해 비교할 수 있습니다.

이 프로그램은 기본계획 단계의 개략검토 도구이며, 편람 제8장 전체의 신호교차로 분석을 대신하지 않습니다.

## 상세 설정 개발본의 적용 범위

공통 조건과 접근로별 조건을 선택할 수 있습니다. 접근로는 북측부터 시계순으로 표시합니다.
계수의 외부 입력은 자동 산정과 구분하며, 새 접근로에 임의의 0.85를 자동 적용하지 않습니다.
외부 계수에는 출처를 기록합니다. 자동 산정한 환산계수는 편집 가능한 숫자칸으로 표시하지 않습니다.

차로 용량 검토는 별도로 켭니다. 정지선 차로별 방향·폭·교통량·방향별 중차량 비율,
첨두시간계수, 진입신호시간, 출발손실·진입신호연장시간을 입력합니다.
차로별 좌·직·우 교통량 합계는 기본 입력과 일치해야 하며, 기본값으로 신호시간을 만들어 넣지 않습니다.
U턴 입력은 해당 차로 유형에서 표시하고, 이 차로 검토에만 반영합니다.
최소 크기에서도 적용·취소 버튼을 고정하고 구역 내부를 스크롤합니다. 마우스 휠은 숫자를 변경하지 않습니다.

계산 범위는 동일 진입신호를 쓰는 차로의 `g`, 포화교통류율 `s`, 용량 `c`, 수요 `v`, `v/c`입니다.
식 8-2~8-4 및 표 8-4·8-12~8-14를 적용하며, 이동류 구성비는 승용차환산 교통량으로 구합니다.
공용차로도 모든 이동류가 동일 신호에 진입하는 조건이어야 합니다.
입력값과 계산 근거는 ‘확인·근거’에서 확인하고 프로젝트에 보존합니다(프로젝트 스키마 4).
이전 버전으로 새 프로젝트를 열면 추가 조건이 반영되지 않을 수 있으므로 같은 개발본 이상에서 열어야 합니다.

**아직 구현하지 않은 범위:** 차로 간 수요 자동 배분, 비보호·보호비보호 겸용좌회전,
적색 우회전의 이동류 분리, 보행 상충·도류화·짧은 부가차로 영향, 대기행렬, 연동,
평균접근지체 및 서비스수준. 해당 조건은 이 차로 용량 검토의 지원 조건에 포함되지 않습니다.
편람 전체 ‘정밀 분석’으로 표기하거나 위 조건에 임의 계수를 대입하지 않습니다.
차로 용량 결과를 입체화 판정의 P·P′에 대입하지 않으며, A·B·C·D 판정과 신호 용량은 별개의 결과입니다.

## 개발 실행

```powershell
python -m pip install -e .
python -m interchange_review
```

## 테스트와 EXE 빌드

```powershell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -v
python validation\scenario_validation.py
python validation\render_ui.py
.\build.ps1
```

로컬 x64 빌드 결과: `dist\K-GSS_v5.1.0.exe`

GitHub Release에는 `K-GSS_v5.1.0_windows-x64.exe`와 `K-GSS_v5.1.0_windows-arm64.exe`를 함께 제공합니다.

기존 2013 편람 기반 최종 상태는 Git 태그 `legacy-khcm2013-v3.9.1`에 보존합니다.
